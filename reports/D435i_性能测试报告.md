# D435i RGB 实时检测性能测试

测试日期：2026-10-04（北京时间）。在当前机载 Orin NX 上实际读取 USB 3.2 连接的 Intel RealSense D435I，运行 `noFFN_fp16.engine`。两轮均完成 10 帧模型预热及 60 秒正式采样，正常退出并释放相机。

## 配置与结果

- 使用系统 Python 3.8.10、PyTorch 2.1.0a0+41361538.nv23.06、OpenCV 5.0.0，以及项目内 `SO_DETR` 的 RTDETR 推理路径。
- 模型输入 640×640，置信度阈值 0.25，CUDA 设备 0。
- 只开启 BGR8 RGB 流，不开启深度和 IMU；无窗口、不在测试循环中绘图或写图片。
- 相机采集线程持续读帧，检测线程只消费最新帧。
- `nvpmodel -q` 返回功耗模式名称 `25W`（模式 3）；读取 EMC 参数时报权限错误，因此未完整验证该模式的所有限制。本次未调整功耗模式或时钟。

| 指标 | RGB 640×480 / 30 FPS | RGB 1280×720 / 30 FPS |
| --- | ---: | ---: |
| 实际测试时长 | 60.05 秒 | 60.05 秒 |
| 检测处理帧数 | 1118 | 1107 |
| **实际检测吞吐** | **18.62 FPS** | **18.43 FPS** |
| 采集帧率 | 29.98 FPS | 29.97 FPS |
| 检测完整调用平均耗时 | 53.62 ms | 54.12 ms |
| 检测完整调用 P95 | 57.50 ms | 57.75 ms |
| 库记录的模型推理平均耗时 | 38.85 ms | 40.60 ms |
| SDK 返回帧到送入检测，平均等待 | 10.61 ms | 11.15 ms |
| SDK 返回帧到送入检测，P95 等待 | 14.67 ms | 15.78 ms |
| SDK 返回帧到结果可用，平均耗时 | 64.24 ms | 65.29 ms |
| SDK 返回帧到结果可用，P95 耗时 | 71.11 ms | 72.33 ms |
| 主动跳过的已采集帧数 | 681 | 691 |
| 测试期间 SDK 帧编号缺口 | 0 | 0 |

这两轮测试中，相机采集保持约 30 FPS，检测处理约 18.5 FPS。720p 与 480p 的检测吞吐相差约 1%，但测试未交替重复、现场画面也存在变化，不能据此确定分辨率影响的精确大小。当前性能主要由模型检测链路决定；模型输入尺寸在两轮中均为 640×640。

主动跳过的帧用于避免应用层队列增长，不代表 USB 丢帧。SDK 帧编号无缺口仅描述本次采样；SDK 返回帧到结果可用的耗时不包含曝光、USB 传输和 SDK 内部缓冲，不能当作相机到屏幕的完整延迟。没有测试窗口显示开销、深度/IMU同时运行、A8 mini RTSP 或长期稳定性。

现场为室内画面，保存图中存在 `car` 等误检。noFFN 的类别表来自模型内置的 VisDrone 航拍 10 类元数据，这次只评估运行性能，不评估检测准确率。

## 复现与产物

```bash
python3 scripts/d435i_detection.py --no-display --duration 60 \
  --output test_results/d435i/rgb_640x480_noffn_fp16

python3 scripts/d435i_detection.py --width 1280 --height 720 --no-display --duration 60 \
  --output test_results/d435i/rgb_1280x720_noffn_fp16

# 在有桌面的机载电脑终端显示画面，Q / ESC / Ctrl+C 退出
python3 scripts/d435i_detection.py --duration 0
```

再次使用上述固定输出目录会覆盖同名结果；省略 `--output` 时自动创建时间戳目录。
